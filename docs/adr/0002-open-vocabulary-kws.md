# ADR-0002：开放词表 KWS 与录音校准

- 状态：已接受
- 日期：2026-07-13

## 背景

系统需要让用户配置自定义唤醒词，并支持把它放在多条命令的开头或结尾。配置过程中可以让用户录制唤醒词，但产品没有“只有录制者才能唤醒”的身份限制需求。

候选方案包括：

1. sherpa-onnx 开放词表 KWS，根据文字、拼音或音素在运行时配置关键词
2. 使用少量用户录音做模板或 Query-by-Example 匹配
3. 为每个固定唤醒词收集数据并训练专用 KWS 模型
4. 使用 Porcupine 等商业自定义唤醒词引擎

## 决策

MVP 使用 sherpa-onnx 开放词表 KWS 作为主检测器。配置层接收唤醒短语及必要的发音信息，生成关键词 token，并保存每个关键词的 `boosting score` 和触发阈值。

用户录音用于现场校准、阈值选择和独立验收，不用于训练用户专属模型，也不提取说话人声纹。系统不做说话人身份判断，录制者以外的用户应当可以正常唤醒。

音频仍然先经过软件 AEC，再进入 KWS 和 20 秒环形缓冲区。KWS 返回的关键词及 token 时间戳用于前置、后置和嵌入位置判断。

## 理由

- 更换关键词只需更新配置，不需要为每个用户重新训练模型
- 预训练的说话人无关声学模型比少量近讲模板更容易覆盖距离、语速和环境变化
- sherpa-onnx 当前提供中英 KWS 模型、INT8 模型、Windows 构建和关键词时间戳
- 开放词表检测与“任何人都可以唤醒”的需求一致
- 录音仍然能为目标房间、麦克风、AEC 输出和实际发音提供有效校准数据
- 前后置唤醒可以共用同一常驻 KWS，不增加第二套检测链路

## 代价

- 用户需要提供可映射成文字、拼音或音素的发音描述
- `boosting score` 和触发阈值仍需在真实负样本上校准
- 开放词表模型不会从几条用户录音中自动学习生造发音
- 说话人无关设计意味着其他人说出相同短语也会触发，这是已接受行为

## 未采用方案

### 录音模板或 Query-by-Example

它最符合“录几遍就学会任意声音”的交互，也适合无法文字化的生造发音。但少量样本容易绑定录制距离、麦克风和语速，在 2 米、音乐和 AEC 残留条件下需要更多数据增强与负样本挖掘。MVP 不把它作为主链路。

### 固定词专用模型

WeKWS 一类方案适合关键词长期固定且能够收集大量正负样本的产品。当前项目允许用户更换唤醒词，为每个短语重新训练和分发模型成本过高。

### Porcupine

Porcupine 支持中文和 Windows，可以快速生成自定义关键词模型，适合作为对照基线。但它需要 Picovoice AccessKey，并引入闭源运行库及相应授权约束，因此不作为本地开源主链路。

### openWakeWord

openWakeWord 的训练工具和推理接口较简单，但其官方当前仅正式支持英语，不适合作为中文主方案。

## 重新评估条件

出现以下任一情况时重新评估 Query-by-Example 或专用 KWS：

- 目标唤醒词无法稳定映射成文字、拼音或音素
- sherpa-onnx 在独立验收集上无法同时满足召回率和误唤醒门槛
- 后续产品新增说话人身份限制需求
- 关键词最终固定，并且已经具备足够的正负训练数据
